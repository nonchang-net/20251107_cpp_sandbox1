# コンポーネントシステムのリファクタリング - 条件付きコンパイルによる統合

## 変更内容の概要

- 各コンポーネントの2ファイル構成（.hと_impl.h）を1ファイル構成に統合しました
- 条件付きコンパイル方式を採用し、`#pragma once`を従来のインクルードガードに変更しました
- 9つの`_impl.h`ファイルを削除し、実装部分を各コンポーネントの.hファイルに統合しました

## なぜこのように変更したか

- 1コンポーネントあたり2ファイルの構成は管理が煩雑で、ファイル数が多くなりすぎていました
- 条件付きコンパイル方式により、Entityクラスの完全な定義が必要な実装部分を適切に分離できます
- `#pragma once`では再インクルード時に実装部分が読み込まれないため、従来のインクルードガードに変更することで、宣言部分と実装部分を独立して制御できるようにしました

### 実装パターン

各コンポーネントヘッダーは以下の構造になっています:

```cpp
#ifndef MYGAME_COMPONENT_H_INCLUDED
#define MYGAME_COMPONENT_H_INCLUDED

// クラス宣言部分

#endif  // MYGAME_COMPONENT_H_INCLUDED

// 実装部分（条件付きコンパイル）
#if defined(MYGAME_ENTITY_DEFINED) && !defined(MYGAME_COMPONENT_IMPL_INCLUDED)
#define MYGAME_COMPONENT_IMPL_INCLUDED

// 実装コード

#endif  // MYGAME_ENTITY_DEFINED && !MYGAME_COMPONENT_IMPL_INCLUDED
```

この方式により:
1. 最初のインクルード時は宣言部分のみが読み込まれる
2. `entity_manager.h`で`MYGAME_ENTITY_DEFINED`が定義された後の再インクルードで実装部分が読み込まれる
3. 宣言部分と実装部分が独立したインクルードガードで管理される
